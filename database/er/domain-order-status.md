# 订单状态与库存流水域 —— 实体、属性与业务规则清单

> 实验二 · 数据库设计 ｜ 主责人：林伟翔（订单状态与库存流水域）｜ 版本 v0.1 · 2026-11-14
> 需求基线：FR-07（主）、FR-05/06/08；B-05、B-06、B-08；NFR-01/02/03 ｜ 依据：database/README.md 分工与建模约定
> 交叉确认：`bouquet.stock_qty`（庞延新）、`orders.status / idempotency_key`（何奕佳）为跨域接口字段，须与相邻域共同定稿后方可进入 ER 图合并。

## 1 本域范围

本域保存**只追加的流水表**，为以下需求提供数据落点：

- B-05：可预订数量表示剩余量，任何时刻不得小于 0，与有效订单一致；
- B-06：仅本人可取消，取消仅回补一次，历史记录保留；
- NFR-02：同一提交或取消请求重复到达，只产生 1 次业务效果；
- G3：全过程留痕（操作人、时间、变更前后值可追溯）。

本域**不定义**订单主表（何奕佳：订单域）、不定义花束主档（庞延新：花束与库存域）。

## 2 实体一：order_status_log（订单状态变更日志）

### 2.1 标识

- 主键：`id`（BIGINT，代理主键，AUTO_INCREMENT）。
- 业务唯一性：同一订单的每次状态变更各占一行，无自然唯一键；变更历史只增不删。

### 2.2 属性清单（每个属性注明来源）

| 属性        | 类型                   | 可空 | 含义                                                     | 来源依据                                         |
| ----------- | ---------------------- | ---- | -------------------------------------------------------- | ------------------------------------------------ |
| id          | BIGINT, AUTO_INCREMENT | 否   | 主键                                                     | 建模约定 4                                       |
| order_id    | BIGINT                 | 否   | 所属订单，外键 → orders.id                               | FR-06（订单查询）、FR-07（取消）；UC-03/UC-04    |
| from_status | VARCHAR(16)            | 是*  | 变更前状态；首条"创建"流水无前状态（NULL，见待确认项 2） | Q-10 状态集合                                    |
| to_status   | VARCHAR(16)            | 否   | 变更后状态；CHECK ∈（有效 / 已取消 / 已完成）            | Q-10（本期仅"有效/已取消"产生流转）；FR-06/FR-07 |
| user_id     | BIGINT                 | 否   | 操作人，外键 → user.id（命名按约定 1），取自登录态       | FR-08；UC-04 P1（记录操作者）                    |
| changed_at  | DATETIME               | 否   | 变更时间，默认 CURRENT_TIMESTAMP                         | UC-04 P1（取消时间）；FR-06                      |
| remark      | VARCHAR(255)           | 是   | 备注（扩展位，如拒绝原因）                               | 预留                                             |

\* from_status 可空性见第 6 节待确认项 2。

### 2.3 本实体约束

1. **只追加**：不提供 UPDATE/DELETE 路径（应用层与权限控制），落点为 B-06（历史保留）与 G3（留痕）。
2. 每次状态流转写一行；状态取值必须与用例一致（有效 / 已取消；"已完成"仅占位，本期不产生流转，Q-10）。
3. `CHECK (from_status <> to_status)`：防止无意义流水（待组内确认）。
4. 订单不物理删除（B-06），本表无级联删除需求。

## 3 实体二：stock_change（库存变更流水）

### 3.1 标识

- 主键：`id`（BIGINT，代理主键，AUTO_INCREMENT）。
- **业务唯一性：`UNIQUE (order_id, change_type)`** —— 同一订单"下单扣减"与"取消回补"各至多一条流水，直接落地：
  - NFR-02（重复请求只产生一次业务效果）；
  - B-06（取消仅回补一次，重复取消不产生第二次回补）。
  - `order_id` 为 NULL（商家调整）的行不参与该约束（MySQL 唯一索引对 NULL 不去重），符合预期。

### 3.2 属性清单

| 属性           | 类型                   | 可空 | 含义                                                   | 来源依据                                     |
| -------------- | ---------------------- | ---- | ------------------------------------------------------ | -------------------------------------------- |
| id             | BIGINT, AUTO_INCREMENT | 否   | 主键                                                   | 建模约定 4                                   |
| bouquet_id     | BIGINT                 | 否   | 花束，外键 → bouquet.id                                | B-05；FR-01～FR-04（跨域：庞延新）           |
| order_id       | BIGINT                 | 是   | 关联订单，外键 → orders.id；商家调整/初始化场景为 NULL | FR-05（扣减）、FR-07（回补）（跨域：何奕佳） |
| change_type    | VARCHAR(16)            | 否   | CHECK ∈（下单扣减 / 取消回补 / 商家调整 / 初始化）     | FR-05、FR-07、FR-02                          |
| quantity_delta | INT                    | 否   | 变化量：扣减为负、回补为正、商家调整可正可负           | B-05 剩余量定义；UC-03/UC-04                 |
| before_qty     | INT                    | 否   | 变更前剩余量快照                                       | G3 留痕；走查对照                            |
| after_qty      | INT                    | 否   | 变更后剩余量快照；**CHECK (after_qty >= 0)**           | **B-05 剩余量非负**                          |
| user_id        | BIGINT                 | 是   | 操作人，外键 → user.id；系统自动扣减的取值见待确认项 3 | FR-08、FR-02                                 |
| created_at     | DATETIME               | 否   | 变更时间，默认 CURRENT_TIMESTAMP                       | 建模约定 1；G3                               |

### 3.3 本实体约束

1. **CHECK (after_qty >= 0)**：B-05 在本域的落点；`bouquet.stock_qty >= 0`（庞延新域）为另一落点，双保险。
2. **UNIQUE (order_id, change_type)**：见 3.1，NFR-02 与 B-06 的落点。
3. `before_qty` 与 `bouquet.stock_qty` 当前值的一致性由**同一事务**保证（扣减/回补与写流水在同一事务提交），MySQL 不支持跨表 CHECK，应用层责任在设计说明中写明。
4. 符号约定：下单扣减 delta 为负、取消回补 delta 为正、商家调整可正可负。

## 4 本域业务规则汇总（供 ER 图与走查引用）

| 规则   | 内容                            | 数据落点                                                     |
| ------ | ------------------------------- | ------------------------------------------------------------ |
| B-05   | 剩余量非负，与有效订单一致      | `stock_change.after_qty >= 0` + `bouquet.stock_qty >= 0` + 同事务写入 |
| B-06   | 取消仅回补一次、历史订单保留    | `UNIQUE(order_id, change_type)`；`order_status_log` 只追加   |
| NFR-02 | 重复提交/取消只产生一次业务效果 | 同上唯一约束 + `orders.idempotency_key`（何奕佳域）          |
| G3     | 全过程留痕                      | 两张流水表只增不删，记录操作人与时间                         |
| FR-08  | 操作人可追溯                    | `user_id` 外键，取自登录态，不接受前端传入                   |

## 5 跨域接口（须与相邻域共同定稿）

| 接口                                                       | 对方域                 | 约定内容                                                     |
| ---------------------------------------------------------- | ---------------------- | ------------------------------------------------------------ |
| `stock_change.bouquet_id` → `bouquet.id`                   | 庞延新（花束与库存域） | `bouquet.stock_qty` 每次变化必须有一条对应流水；两表 CHECK 双保险 |
| `order_status_log.order_id` → `orders.id`；`orders.status` | 何奕佳（订单域）       | 状态每次变化写一行日志；`idempotency_key` 唯一约束定义在 orders 表，本域不重复定义 |

## 6 本域待组内确认项

| #    | 问题                                                         | 当前建议                                                     |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 1    | 下单成功是否写一条"→ 有效"的初始化状态流水                   | 建议写，保证追溯完整                                         |
| 2    | `order_status_log.from_status` 首条流水取 NULL 还是占位状态值 | 建议 NULL（语义：无前状态）——约定 3 要求状态枚举与用例一致，不宜引入"新建"等枚举外值 |
| 3    | `stock_change.user_id` 在系统自动扣减时填什么                | 约定"系统"账号，或允许 NULL                                  |
| 4    | 状态 CHECK 是否预留"已完成"枚举值                            | 按 Q-10 预留，本期不产生流转                                 |

## 7 与实验一成果的对应（走查素材）

- UC-04 第 6 步（条件更新订单状态）→ orders 条件更新（何奕佳域）+ `order_status_log` 插入 + `stock_change` 插入，**同一事务**（对应 A6 回滚保证）。
- UC-04 第 7 步（回补 +N）→ `stock_change`（change_type=取消回补，quantity_delta=+N）。
- UC-03 第 7 步（原子扣减）→ `stock_change`（change_type=下单扣减，quantity_delta=-N）。
- AC-UC04-02 / AC-UC04-08（重复与并发取消）→ `UNIQUE(order_id, change_type)` 保证。
- 本地演示程序已走查的 A1—A6 分支与本域约束一一对应（A5 并发未做正式压测，设计层以唯一约束兜底）。
