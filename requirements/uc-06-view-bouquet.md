# UC-06 查看花束详情 —— 详细用例

## 1 用例基本信息

| 字段 | 内容 |
|---|---|
| 编号 | UC-06 |
| 名称 | 查看花束详情 |
| 目标 | 顾客了解所选花束的当前信息与可预订状态，决定是否进入下单。 |
| 主要参与者 | 顾客 |
| 次要参与者 | 商家维护花束信息和上下架状态；管理员可强制下架违规花束，不参与顾客查看流程。 |
| 触发条件 | 顾客从UC-02选择花束，或访问已有详情链接、刷新详情。 |
| 前置条件 | 系统提供详情入口并接收花束标识。标识是否有效、花束是否存在、仍上架或有余量均在读取时判断，不作为排除异常的前置条件；身份与入口策略遵循FR-08。 |
| 成功后置条件 | 对当前可预订花束展示约定字段并提供UC-03入口；售罄、下架或无效标识显示对应反馈并禁用入口。查看本身不生成订单，不扣减或回补数量。 |
| 失败后保证 | 不改变花束、数量、状态或订单；读取失败时保留所选标识，允许重试，不把旧价格和库存作为已确认的当前信息，预订入口保持禁用。 |

## 2 输入与输出

| 项目 | 说明 |
|---|---|
| 输入 | 花束标识；由UC-02进入时可保留原检索条件以便返回。 |
| 正常展示 | 图片、花名、花语与适用场景、单价（元/束）、当前剩余可预订数量（束）、商家信息、最早可送达日期。 |
| 日期来源 | 与UC-03共用同一日期规则，不另行计算一套。具体来源、计算方式及节日清单按Q-03后续落实；当前文档不编造日期或承诺“次日必达”。 |
| 可预订入口 | 当前已上架且剩余量大于0时可进入UC-03；日期的最终合法性及库存仍在下单提交时重新校验。进入UC-03不等于创建订单。 |
| 异常反馈 | 售罄、已下架、标识无效或记录不存在、读取失败；均不提供当前可用的预订入口。读取失败与花束不存在分别说明。 |

## 3 正常流程

| 步骤 | 顾客动作 | 系统响应 |
|---|---|---|
| 1 | 从结果列表选择花束，或打开详情链接。 | 接收花束标识，读取期间不启用预订入口。 |
| 2 | — | 校验标识并读取当前记录；标识无效或不存在转A3，读取失败转A4。 |
| 3 | — | 重新判断当前上下架状态与剩余量；下架转A2，售罄转A1，不能沿用列表的旧库存判断。 |
| 4 | — | 展示图片、花名、花语/场景、元/束单价、剩余量（束）、商家与最早可送达日期；日期采用与UC-03一致的来源和规则（Q-03具体算法仍待落实）。 |
| 5 | 查看信息并选择“立即预订”。 | 向UC-03传递花束标识；UC-03读取当前信息并校验数量、日期和状态，提交成功才创建订单与扣减库存。 |
| 6 | 或选择返回检索。 | 返回UC-02并保留进入前的条件与排序；重新查询读取当前状态。 |

## 4 异常与备选流程

### A1 列表展示后售罄（分支点：第3步）

- 触发：其他有效预订使当前剩余量变为0。
- 反馈：显示最新数量0及“已售罄”，禁用预订入口，允许返回检索。
- 结果：查看不再扣减数量，不新增订单；若以后数量回补，刷新后按新状态重新判断可预订性。

### A2 花束已下架（分支点：第3步）

- 触发：商家或管理员在顾客查看前将花束下架，顾客仍使用旧列表或链接。
- 反馈：提示“该花束已下架，当前不可预订”，禁用入口，提供返回检索操作。
- 结果：旧详情不被当作仍可售；不更改已有订单、花束状态或库存。下架不因此取消历史订单。

### A3 标识无效或记录不存在（分支点：第2步）

- 触发：链接中的标识无效，或没有对应记录。
- 反馈：提示“花束不存在或不可用”，不显示可预订入口；清除可能残留的其他花束详情，允许返回检索。
- 结果：不伪造详情，不生成订单，不修改任何记录；此异常不表示本期新增删除功能。

### A4 详情读取失败（分支点：第2步及刷新）

- 触发：请求超时、网络断开或数据读取失败。
- 反馈：提示“详情加载失败，请重试”，保留花束标识；入口禁用，旧信息不作为当前值。
- 结果：重试重新读取并执行第2～4步，成功后按最新状态展示；不能直接把失败解释为无效花束。

### A5 进入下单后状态又变化（衔接点：第5步）

- 触发：详情可预订，但顾客进入UC-03后花束售罄或下架。
- 反馈：由UC-03按其A2/A6等流程重新校验并拒绝失效预订，显示当前原因。
- 结果：详情展示不是库存锁定或订单承诺；UC-06本身仍不扣减数量。
